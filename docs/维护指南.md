# 维护指南

## 项目边界

- `frontend/` 只负责浏览器界面与静态资源，通过 `/api/v1/chat` 调用后端。
- `backend/` 负责对话、PostgreSQL、管理后台和请求追踪。
- `deploy/` 只放部署脚本与无密钥配置示例。
- `assets/source/` 和 `tools/` 是制作源材料，不进入线上静态目录。

## 用户请求链路

1. `RequestLoggingFilter` 为 `/api/**` 与 `/manage/**` 生成 `X-Request-Id`。
2. HTTP 方法、路径、状态、耗时、IP、User-Agent、操作者和会话编号写入 `request_log`。
3. 聊天请求的用户/助手消息使用同一 `request_id` 写入 `conversation_message`。
4. 管理员在 `/manage/requests` 查看最近 200 条操作，并进入详情查看聊天内容、提供方、命中意图与置信度。
5. 日志写入失败只记录服务器警告，不影响用户原请求。

日志不收集 Cookie、密码、授权信息或 URL 查询参数。上线长期运行后应增加保留策略，例如每天删除 90 天以前的请求记录。

## 常用验证

```powershell
cd frontend
npm test

cd ..\backend
mvn test package
```

服务端部署后执行：

```bash
PUBLIC_ORIGIN=http://127.0.0.1:21114 /opt/testproject/deploy/verify-deployment.sh
```

## 临时文件

以下目录都可重新生成，不应提交：

- `frontend/node_modules/`
- `frontend/.next/`
- `frontend/out/`
- `backend/target/`
- `tmp/`

庞菠菠原始参考图放在 `assets/source/pangbobo-reference/`，可维护的 Blender/转换脚本放在 `tools/pangbobo/`，最终供网页加载的文件才放入 `frontend/public/pangbobo/`。
